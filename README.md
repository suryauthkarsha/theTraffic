theTraffic. is an open civic-data explorer for Bengaluru's traffic signals, published timing plans, community-mapped surveillance infrastructure, and account-free road grievances. It makes uncertainty visible instead of turning incomplete or stale data into confident claims.

## What you can explore

- **Signal map:** 579 logical intersections reconstructed from 1,392 OpenStreetMap signal nodes, with directional approaches and source provenance.
- **Published timing plans:** Bengaluru Traffic Police sheets made available through OpenCity, parsed into normalized factual records. A plan reaches estimates only after an explicit, committed review decision.
- **Junction-level estimates:** expected stop probability and delay from a fixed-time plan with an accepted review link. No exact lamp state is claimed when synchronisation is unknown.
- **Surveillance map:** 2,818 `man_made=surveillance` records from a dated OpenStreetMap snapshot, kept separate from signal data.
- **Account-free grievance board:** public reports about potholes, footpaths, water logging, crossings, signals, street lights, parking, and encroachment — each with a photo of what is wrong (required), and the place and words when given. Posts may contain identifying words, visible image details, coordinates, and times.
- **Research and methodology:** provenance, coverage, limitations, model definitions, and reproducible ingestion scripts.

> [!IMPORTANT]
> theTraffic. is not a live traffic-control feed. The shipped timing documents are dated 2010 to 2018 and are treated as stale evidence. Surveillance entries are community-mapped records, not proof that a device is active, monitored, police-owned, or capable of a particular form of detection.

## Quick start

### Prerequisites

- [Bun](https://bun.sh/) 1.4.2
- Node.js 22 or newer
- Python 3.11 or newer only if you want to run the ingestion pipeline

### Run the web app

```bash
git clone https://github.com/suryauthkarsha/theTraffic.git
cd theTraffic
(cd web && bun install --frozen-lockfile && bun run dev)
```

Open <http://localhost:8080>. No API key is required for the frontend or bundled datasets.

### Verify a change

```bash
# Run these from the repository root
(cd web && bun run lint && bun run typecheck && bun run test && bun run build)
bun test functions/tests scripts/tests
(cd functions && npm ci && npm run typecheck && npm run build)

# Python ingestion tests
python3 -m pip install -r requirements-dev.txt
python3 -m unittest discover -s scripts/tests -v
```

The production build includes an environment-hygiene gate and fails if a credential-like value reaches a generated text asset.

## Configuration

Copy the root template to `web/.env.local`:

```bash
cp .env.example web/.env.local
```

All settings are optional. The main ones are:

| Variable | Purpose |
| --- | --- |
| `VITE_SUPPORT_EMAIL` | Support-page mailbox |
| `VITE_GA_MEASUREMENT_ID` | Enables GA4 page views; Google's counter is off when empty (DataFast needs no value) |
| `VITE_GRIEVANCE_API_URL` | Overrides the grievance Worker origin |
| `VITE_SITE_URL` | Canonical public origin and sitemap base |
| `VITE_MAP_STYLE_URL` | Custom MapLibre style |
| `VITE_SATELLITE_TILE_URL` | Custom satellite tile template |

Never commit a real `.env` file. The complete template and deployment notes are in [.env.example](.env.example) and [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Architecture

```text
web/          React 19 + TypeScript + Vite + MapLibre frontend
  public/data Versioned, static research datasets
  src/        Pages, maps, models, provenance, tests
functions/    Cloudflare Worker + Durable Objects for grievances
scripts/      OSM sync, dataset builders, and timing-plan ingestion
data/         Source snapshots and reproducibility logs
docs/         Architecture, methodology, deployment, privacy, routing history
```

The signal and surveillance views use static versioned datasets. Only the grievance pages call the project's Worker. There are no user accounts, no route planner, and no visitor-profile database. Read the detailed [architecture](docs/ARCHITECTURE.md) and [privacy design](docs/PRIVACY.md).

## Data principles

1. **Provenance before polish.** Every published claim should identify its source and observation date.
2. **Unknown means unknown.** Missing timing data is never described as an untimed junction.
3. **Review before prediction.** Parsed plans do not affect estimates until a committed decision accepts the junction match. If no approach-to-phase mapping is recorded, the model marginalizes across vehicle phases and says so.
4. **Separate unlike datasets.** Surveillance records are not merged into the signal model.
5. **No unauthorised feeds.** The project does not scrape private traffic or signal APIs.
6. **Minimise personal data.** Grievances have no identity field, reject contact details, and strip JPEG metadata.

## Contributing

Contributions are welcome, especially:

- data corrections backed by a public source;
- accessibility, performance, and mobile improvements;
- ingestion and validation tests;
- clearer uncertainty and provenance explanations;
- security and privacy hardening.

Start with [CONTRIBUTING.md](CONTRIBUTING.md). Use the issue templates for bugs, feature ideas, or data corrections. Please report vulnerabilities privately through [GitHub Security Advisories](https://github.com/suryauthkarsha/theTraffic/security/advisories/new).

## Project status

This is active research software and a civic-data interface, not a navigation or safety-critical system. APIs, schemas, and datasets may change. The default branch is the supported version.
